## Context

当前宠物系统已经支持三题陪练、家具任务、成长阶段和本地参与事件，但宠物反馈主要是短文本/静态图标，主动邀请只在少数页面出现，完成后缺乏跨课次的目标承接。实现必须继续复用现有练习进度、教材选择、宠物成长和本地 SharedPreferences 存储，并保持离线、低压力和可访问。

## Goals / Non-Goals

**Goals:**

- 用有限的状态机表达可预测的宠物动作和房间联动，支持 reduced motion。
- 让主动任务由学习状态驱动、按教材和本地日期限频，并允许忽略或稍后处理。
- 提供当前教材/单元的可解释目标、完成进度、下一步行动和结果预览。
- 保持事件数据可审计、隐私白名单和未来 gRPC 适配边界。

**Non-Goals:**

- 不加入连续打卡、饥饿/衰减、排行榜、竞争、额外货币或新的学习评分。
- 不改变题目选择、批改、错题、掌握度和成长奖励算法。
- 不在本阶段加入网络上传、账号系统或复杂宠物动画资源包。

## Decisions

### 1. 使用小型动作状态机，而不是逐帧动画系统

新增 `PetAction` 和短反馈序列，将事件映射为 idle、invite、think、celebrate、encourage、complete、repeat 等有限状态；房间使用对应的 `FurnitureFeedback` 状态。这样可以使用现有 Flutter 图标/颜色和 AnimatedSwitcher，在 reduced motion 下退化为静态语义状态。相比引入动画资源或第三方库，这更容易测试、跨平台一致且不会增加包体。

### 2. 主动任务采用确定性本地调度

新增 `PetInvitationScheduler`，输入教材、单元进度、最近事件、入口和本地日期，输出零或一条邀请。每天最多展示一次、接受后冷却、用户跳过后当天不再打扰；优先选择存在明确缺口的当前单元目标。调度使用安装 ID/本地日期做稳定选择，不依赖网络或随机数。

### 3. 目标使用纯投影模型

新增 `PetLearningGoal` 和 `PetLearningGoalProgress`，从现有教材内容与练习记录计算目标，不单独维护可漂移的计数器。目标分为课文掌握、词语掌握和三题陪练三种，显示当前值、目标值、剩余量、行动标签和完成后的家具/动作结果。完成状态由现有 claimed events 或进度记录决定，避免重复奖励。

### 4. 复用现有事件 outbox

扩展 `EngagementEventType` 和 typed context，记录主动邀请展示、接受、跳过、目标查看和目标驱动启动；不记录答案、音频、自由文本或学生身份。指标仍由事件投影计算，事件写入失败不阻塞学习流程。

## Risks / Trade-offs

- [Risk] 过多动作会分散注意力 → 每次答题最多一个短反馈，默认不播放声音，完成反馈可被 reduced motion 压缩。
- [Risk] 主动邀请被感知为打扰 → 每日展示和接受冷却、可跳过、无负面文案，并只在有明确学习缺口时出现。
- [Risk] 目标投影在教材数据变化后跳动 → 使用当前教材/单元快照和稳定排序，不持久化派生计数；展示“约/剩余”时使用明确的当前范围说明。
- [Risk] 旧宠物档案缺少新字段 → 所有新模型采用默认值和容错解析，首次读取时平滑迁移。

## Migration Plan

1. 增加模型和纯函数测试，再接入现有页面；旧档案读取时使用默认动作、调度和目标状态。
2. 将主动调度、目标卡和动作反馈作为可选 widget/服务接入，保留现有入口作为回退。
3. 运行 Dart 格式化、静态分析、定向测试和全量测试。
4. 若需要回滚，移除新入口即可；不会删除已有成长、练习或事件数据。

## Open Questions

- 后续真实试用后再调整每日邀请冷却和目标阈值；V7 先使用可测试的固定策略。
- 未来接入 gRPC 时沿用现有事件版本和 typed context，不在本变更提前确定服务端协议。
